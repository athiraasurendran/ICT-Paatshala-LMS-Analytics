# Confidentiality and Public Portfolio Boundaries

This repository is a high-level professional case study, not a copy of the internal project.

## Do not publish

- Original or derived company datasets.
- Actual KPI values, company-specific metric tables, or detailed internal findings.
- Student, learner, trainer, or programme identifiers.
- Screenshots or recordings of the internal dashboard.
- Internal source code or implementation details not approved for release.
- Internal URLs, credentials, environment files, API keys, or secrets.
- Any material restricted by organisational policy, contract, or supervisor instructions.

## Included in this repository

- General project objectives and analytical questions.
- A high-level description of the tools and workflow.
- Conceptual workflow and architecture diagrams.
- A general description of the dashboard's purpose.
- An interview-safe project summary.

## Before publishing

Review the internship agreement and applicable organisational policies. If you are unsure whether a detail is public, leave it out or seek written permission. Anonymising information does not automatically make its publication permissible.

## If confidential content was previously committed

Editing a file removes content from the current version, but the old content may remain in Git history, forks, or cached copies. If secrets or sensitive information were exposed, remove the exposure promptly and follow the relevant incident or credential-rotation process. For ordinary wording changes, a normal edit and commit is usually sufficient.
